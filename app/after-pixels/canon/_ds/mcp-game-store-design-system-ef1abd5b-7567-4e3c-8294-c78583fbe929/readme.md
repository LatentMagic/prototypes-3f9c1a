If creating visual artifacts (slides, mocks, throwaway prototypes, etc), copy assets out and create static HTML files for the user to view. If working on production code, you can copy assets and read the rules here to become an expert in designing with this brand.
## Working with the design system owner
The design system's owner reviews work in a separate session and relays answers. Keep questions to a minimum.
- If the design system covers a choice (readme, guidelines, a component's prompt.md), follow it. Don't ask.
- If it doesn't, make the smaller choice that stays consistent with what's already there, and list it under "Decisions I made" in your summary.
- Ask only about changes to copy, flows or data, or when two parts of the system contradict each other. Put every question in one numbered list at the end of a finished piece of work, never one at a time.
- Report when the work is done, not after each step.

If the user invokes this skill without any other guidance, ask them what they want to build or design, ask some questions, and act as an expert designer who outputs HTML artifacts _or_ production code, depending on the need.
