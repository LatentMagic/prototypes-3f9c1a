# Native app icons

The icon sources for the Circlists native app (the Capacitor wrapper, Android and iOS). They use the installed icon's composition: the frozen mark with its halo at **72% of the visible tile**. Only the format each OS asks for changes. Why the installed icon takes a cream ground: [../../circlists-brand.md](../../circlists-brand.md) §2.

All rasters are 1024×1024.

## Inputs for `@capacitor/assets`

Copy these three into the mobile app's `assets/` folder. The tool generates every per-density file from them.

- `icon-only.png`: the iOS app icon and the Android legacy icons (`ic_launcher`, `ic_launcher_round`). Opaque cream with no alpha channel, because the App Store rejects one. Pixel-identical to [../icons/app-store-icon-1024.png](../icons/app-store-icon-1024.png).
- `icon-foreground.png`: the Android adaptive-icon foreground. The mark on transparency.
- `icon-background.png`: the Android adaptive-icon background. Full-bleed cream, opaque.

The tool insets each adaptive layer by 16.7% a side, so the 1024 source lands on the inner 72 dp of the 108 dp layer, the part a launcher shows. The halo comes out at about 52 dp. That is inside Android's 48–66 dp logo guide and its 66 dp zone that no mask cuts.

## Layers the tool does not make

Add these by hand after the tool has run.

- `ic_launcher_monochrome.xml`: the Android themed-icon layer (Android 13+), as a vector drawable. It is the mark as a silhouette: the halo and disc are solid and the white ring is cut out as a gap. This is the same geometry as the notification badge ([../icons/notification-badge.svg](../icons/notification-badge.svg)), because Android reads only the layer's shape and tints it. It is a full 108 dp layer with the halo placed directly, so reference it **without** an inset. Put it in `res/drawable/` and add one line to both `mipmap-anydpi-v26/ic_launcher.xml` and `ic_launcher_round.xml`:
  `<monochrome android:drawable="@drawable/ic_launcher_monochrome" />`
- `icon-monochrome.png`: the same silhouette as a raster, black on transparency, framed like `icon-foreground.png`. It is a preview. Use it in place of the XML only if a raster is needed, and then with the same 16.7% inset as the other layers.
- `ios-icon-dark.png`: the iOS dark appearance. The mark on transparency, so the system's dark ground shows through. Byte-identical to `icon-foreground.png`; it carries its own name so each slot has an obvious file.
- `ios-icon-tinted.png`: the iOS tinted appearance. The silhouette in white on opaque black. iOS tints by brightness, so the shape has to be the light part. Using the silhouette means iOS and Android theme the icon the same way.

In Xcode, set the app icon's Appearances to **Any, Dark, Tinted** and drop `icon-only.png`, `ios-icon-dark.png` and `ios-icon-tinted.png` into the three slots.

## Re-running the tool undoes the hand-added layers

Every run of `@capacitor/assets` (3.0.5) rewrites `ic_launcher.xml` and `ic_launcher_round.xml` from a fixed template, which drops the `<monochrome>` line. On iOS it also deletes every other file in `AppIcon.appiconset` and rewrites its `Contents.json`, which removes the dark and tinted icons. So add the layers again after each run, or script that step to run after the tool.

The tool has two weaknesses on Android, and neither comes from these files:

- It draws the adaptive foreground at the legacy icon sizes (48–192 px) and stretches it about 1.5× into the 72 dp it occupies, so the mark is slightly soft.
- It insets the background by 16.7% as well, so the outer 18 dp of the layer, which Android uses for its motion effects, is transparent.

To avoid both, replace the generated foreground PNGs with ones drawn at 72 dp × density, or use a vector foreground and a full-bleed background with no inset.
