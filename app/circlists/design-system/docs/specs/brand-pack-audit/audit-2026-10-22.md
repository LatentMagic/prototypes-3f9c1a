# Brand pack audit — 2026-10-22

Design system compared with the brand pack (`circlists-brand-pack-2026-10-22`, `brand/circlists-brand.md` and `brand/assets/`) and the prototype (`LatentMagic/prototypes-3f9c1a` @ `e8ec4a56d399`, `app/circlists/canon/tokens.css`, `circlists.html`). The whole project was searched. Written before any change.

## Behind

### Assets
1. **Every shared SVG differs in bytes, not geometry.** Pack mark, favicon, wordmark ×2, lockup ×2, notification badge and the three motion files carry a C2PA provenance `<metadata>` block. With that block removed, each matches the design system's file exactly. All shared PNGs and `favicon.ico` already match byte for byte.
2. **Files in the pack that the design system lacks:** `mark/circlists-mark-512.png`, `-1024.png`; `wordmark/*-1024.png`, `*-2048.png` (ink and reversed); `lockup/*-1024.png`, `*-2048.png` (ink and reversed); `icons/favicon-notification.svg`, `-16.png`, `-32.png`; `icons/notification-badge-96.png`; `icons/app-store-icon-1024.png`; `icons/play-store-icon-512.png`; all of `native/` (7 files); the per-folder `README.md`s.
3. **Layout.** The pack sorts its assets into `mark/ wordmark/ lockup/ icons/ motion/ native/`. The design system keeps them flat in `assets/brand/` (motion aside).
4. **`motion/circlists-motion.md`** is older: its timestamp is 2026-07-11 (the pack's is 2026-10-22), its links point one level too shallow, and it has no "Validating the motion" section.

### Colour
5. **Missing from the colour cards:** accent soft `#ECFDF5` (reserved, focus-ring background only), border strong `#0A0A0A`, scrim `rgba(10,10,10,0.40)`. All three are tokens already; no card shows them.
6. **Names.** The spec names Emerald, Sage, Ink, Cream and White. The cards say "Accent", "Page" and "fg-1" and never use the brand names.

### Type
7. **No card lists the type scale.** Weights (400–700), the nine sizes, the four line heights and the three tracking steps are all tokens, but the cards show only headings and body pairings. The spec lists them separately.
8. **Mono uses.** The spec lists standalone link text and status pills ("Coming soon") as mono's uses. The Mono card leaves out both.

### Links
9. **The standalone link form is missing.** The design system shows only the inline link (`cards/pattern-inline-link.html`). The spec's standalone form (JetBrains Mono, Ink, border-1 underline at rest, Ink on hover) has no card or guidance.
10. **The inline link card has no reduced-motion rule.** The prototype's `.circ-doorlink` (circlists.html:330–332) turns the transition off under `prefers-reduced-motion`. Every other value on the card matches.
11. **The README never mentions links.** The underline is always present, and there are two forms.

## References disagree (not resolved)

1. **Standalone link face.** The spec says JetBrains Mono. The prototype's bare `a` rule sets no font, so a standalone link renders in whatever face surrounds it. The spec says itself that "the mono face is this spec's; the rule sets none".
2. **The prototype's own `_ds/` copy** (`canon/_ds/cirlists-design-system-019dca0f-…/tokens.css`, 13026 bytes) is not this system's current `tokens.css` (12961 bytes), so the copy the prototype carries is out of step. That's for the prototype to refresh.
3. **The prototype's `canon/brand/`** is the older pack, which the brief says is not a reference. The design system's PNGs match it and the new pack alike; its SVGs lack the provenance block.
4. **Destructive's scope.** The spec and `tokens.css` both say destructive is "used in v1 only on the last-member Leave primary action". The design system's README (from ui.md) and its Delete dialog card use it for every destructive confirm and the control that opens it. **Resolved 2026-10-22, ratified by the owner:** the brand spec's usage note is stale. Destructive is the colour for destructive actions and errors; the README and Delete dialog stand. As a general rule, a design system says that a token exists and what role it has, not where a product uses it.
