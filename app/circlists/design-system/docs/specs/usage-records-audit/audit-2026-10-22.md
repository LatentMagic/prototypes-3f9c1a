The whole project was searched: `tokens.css`, `components/`, `cards/`, `guide/`, `README.md`, `SKILL.md`. Provenance (where a value was mirrored from: `github.md`, the header of `tokens.css`, "Lifted from…" comments) is not a usage record and stays. Sample content in cards ("Book club", "Delete this link?") is demo copy, not a record.

## B. Borderline — a rule tied to a named product surface

1. `guide/behaviour.md`: "No skeleton cards. The pending feed card's in-place shimmer is the exception." The exception is a rule, but it's stated as one product surface.
2. `guide/content.md`: "Cards are **waiting** (Active) or **finished**. Tabs are **Active** and **History**." This is product vocabulary from the copy voice. It's a rule about words, but it names the product's screens.
3. `tokens.css` size comments: "card titles (mobile)", "card body / dialog body", "dialog titles, page H2". These read as roles (what the size is for), so they probably stay. "Card" here is the product's feed card, not a component this system ships.
4. Pattern cards that are product compositions rather than inventory parts: Feed card, Tabs, Add button, Card menu, Copy control, Checklist row and chip, New pill and waterline, Delete dialog. Each shows a real product instance. Under the definition, each should be either promoted to a component with its rules or kept as a reference.

## Note

`tokens.css` comments currently mirror the prototype's word for word. Changing them makes this system's comments diverge from the prototype, which is upstream. That's in line with the definition, but the prototype would need the same edits for the two to agree again. That would go in the prototype's update list.

## Decision

2026-10-22: the owner delegated these calls ("do as you best see fit"). Applied:

- **A**: every row, as proposed.
- **B1**: rewritten as a general rule: no skeleton placeholders; an item still arriving may shimmer in place.
- **B2, B3**: kept. They are standing rules about words and roles, not records of use.
- **B4**: kept as reference cards. Promoting them to components is build work, not hygiene.

For the prototype's update list: the `tokens.css` comments changed in A (destructive, 3xl, new words, arrival wash, dense touch) now differ from the prototype's.
